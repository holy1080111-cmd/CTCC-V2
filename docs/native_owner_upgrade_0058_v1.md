# Reviewed owner installation: physical57 to physical58

`python -m scripts.native_owner_upgrade_0058_v1` defaults to read-only. The
reviewed private inputs bind the exact source commit, tree, archive, canonical
manifest, actual58 migration, certificate, physical cluster/database/owner and
three existing restricted Demo role names and OIDs. Source58 and physical57 are
reported separately. No historical57 observation is relabelled58.

The owner DSN and reviewed pins remain private files. The configured three Demo
connections must use the same verified TLS route and existing44-grant profile.
The command checks stopped, expired, disarmed local controls, persistent EStop,
and zero active/uncertain local exposure before DDL. This local check does not
prove that the exchange account is flat; account ingestion and reconciliation
remain mandatory before startup and any later Arm.

Only `--execute --confirmation "UPGRADE CTCC OWNER DB0057 TO DB0058"` enables
DDL. This installs the exact reviewed migration and executes zero grants. No
Live key, dedicated Live writer, new Control or Arm is created. The four new
Live DATA tables and their functions must remain accessible only to the owner.

Under one owner transaction, advisory lock, revision lock and locks on every
retained public table, the command re-reads all retained rows, role state and
catalog. It runs the real migration in a savepoint, observes actualhead58, and
verifies all old rows and relation OIDs unchanged, all four new tables empty,
and no nonowner Live grants. It then rolls the savepoint back and verifies the
entire original physical57 state restored. It runs that migration again and
requires the same logical definitions and complete ACL as the rehearsal.
Fresh allocation OIDs and internal FK trigger names are normalized only in
this catalog comparison. Actual revisions, actors, retained table OIDs and
rows are never projected or rewritten.

After the sole COMMIT, new independent owner/three-role sessions must observe
actualhead58, its complete58 protective/native graph, the same physical server,
all retained rows and the exact committed catalog. Any uncertainty during
COMMIT returns `owner_profile_0058_commit_unknown_do_not_retry`. A late failure
returns `owner_profile_0058_committed_readback_required`. Neither is retried,
automatically downgraded, cleared or treated as failure of an already accepted
exchange state.

For an already installed58 database, supply its reviewed
`installed_catalog_sha256` from the postcommit receipt in the private pins.
This binds the logical catalog/ACL, exact migration bytes and Live specification.
The command independently rechecks the source, physical actor, restricted
profile, stopped inventory and installed digest, then returns
`ALREADY_INSTALLED_READBACK_PASS` without DDL, grants or restoring Arm. Changed
schema, ACL or migration/specification requires explicit review; the command
does not invent a replacement baseline. The field is DATA, not an execution
permit.

Rollback uses the source's unchanged58 downgrade policy: retained original OCO
outcomes, Live rows or Live grants refuse downgrade. An uncertain commit first
requires read-only reconciliation. This installer never deletes retained rows,
revokes protection, cancels orders, closes positions, starts services or arms.

The isolated hosted owner component tests real upgrade/rehearsal/rollback and
injected privilege drift using synthetic local stopped rows. Unit transport
fakes and collection-only runs are not SQL acceptance. These tests make no
provider, strategy, profitability, Gate3 or real Live acceptance claim.
