# Original OCO reporting on physical DB0058

The normal Demo entry retains the original bracket. A complete original OCO
exit follows the existing raw journal and risk ledger, with no local close
intent. This reporting branch grants no order or retry authority.

While the genuine recovery source is live, the reporter reconstructs the
original and terminal raw groups with `native_protective_forensics_v58`. It
appends the canonical forensic receipt before the flat transition and reads
it in another committed transaction. The immutable flat witness binds that
receipt. Fees/fills and fixed candidate geometry are replayed; missing funding,
price path and quote references remain unknown.

The original recovery then closes its observed HTTP/SDK resources, disposes
its two NullPools and retires its original source, selector and caller records.
A separately prepared, nonconstructible, same-task DATA writer retains only
the shared SQL writer and its exact original role/factory/TLS pins. It does
not call `journal._source` or reopen the retired selection. A structured
receipt records the actual closed GETs and the two observed pool retirements.

Only after that retirement does the independent writer verify the complete
physical58 role/catalog/ACL graph, lock the same account and scope, and atomically
append cleanup, report-ready and the existing eligible spool. A different
session and transaction ID must replay the committed spool, complete raw
journal, closure and numerical forensics before the HTTP result may say
`durable_pending_projection` and return its spool ID.

Any reporting/commit/readback failure leaves reporting pending. It cannot
change the confirmed exchange/flat/resource result or cause another order.
The existing independent projector and outbox worker perform filesystem and
Notion delivery. Their existing no-clobber, idempotency and accepted-evidence
rules still apply. An accepted spool is never replaced; inconsistent bytes
fail closed. Restart does not fabricate proof of an old process's transport
cleanup. A new DATA recovery can only record its own observed read retirement.

The additive58 SPEC replaces the installed report eligibility function under
the same name/signature and 44-grant profile. Its original55 tail is unchanged.
The new58 submission trigger positively binds the two new acknowledged DATA
versions to the existing original-OCO closure and pre-flat forensic receipt.
Legacy55/56/57 report observations continue to expect their exact prior body.
Only the sole0058 migration may install this SPEC. Importing it installs no SQL.

The public-schema integration module
`test_native_original_oco_reporting_0058_pg.py` uses declared synthetic raw and
cleanup ingress. It retains actual public native triggers, exact physical58
roles and TLS connections, and exercises positive spool replay and wrong
forensic/report rejection. Those tests are engineering validation and do not
establish an actual exchange, SDK cleanup, Demo or Live acceptance.
