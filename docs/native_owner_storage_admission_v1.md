# Owner maintenance: native storage admission

The current read-only retained-0017 tool and canonical 0055→0056→0057→0058 owner chain first inspect fixed `pg_catalog` metadata. They refuse unknown table/index access methods before selecting even `alembic_version`, opening an application table, counting local exposure, reading storage size, or deparsing stored expressions. Existing route/source/TLS, role, schema, stop/flat, migration rehearsal, rollback, commit, and independent readback checks remain required.

`scripts/native_owner_heap_am_v1.py` admits ordinary persistent heap tables and their attached TOAST tables only. Rewrite rules, RLS, foreign/partitioned/view paths and unsupported column types fail closed. Marker shape is checked before its native lock and again while the lock is held. Canonical role observations keep the reviewed marker/table locks across their separate sessions.

The effective `default_table_access_method` must also be exactly `heap` before any head/upgrade read. An unused custom AM could otherwise be selected by the frozen migration's later `CREATE TABLE` despite every existing table being native. The helper refuses this drift; it does not reset the setting or rewrite migration DDL.

`scripts/native_owner_index_catalog_v1.py` admits the source's native btree profile. It checks the handler, complete source-defined operator-family support/operator sets, default operator classes, operators and their estimator/join callbacks, internal routine definitions, and native type-I/O pointers. Unknown key expressions, opclasses, predicates, collations and dependency edges are refused. Permitted partial predicates use only the source's closed native expression forms. Raw constant type IDs in defaults, CHECK constraints, trigger WHEN conditions and parsed function defaults/bodies are checked before subsequent catalog deparsers can reach a type-output callback. The shared row snapshot repeats this global metadata proof and admits no application rows until every returned layout is accepted.

The fixed source facts are `scripts/native_owner_pg17_btree_facts_v1.json`, SHA256 `54a2bd07dc7d905ff3844c0f49b9035daa2997a5271c8a6670f57f53a2d3de41`. They retain each primary input hash and are derived from PostgreSQL's exact `REL_17_11` catalog files: [pg_type.dat](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_type.dat), [pg_type.h](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_type.h), [pg_proc.dat](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_proc.dat), [pg_operator.dat](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_operator.dat), [pg_opclass.dat](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_opclass.dat), [pg_opfamily.dat](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_opfamily.dat), [pg_amproc.dat](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_amproc.dat) and [pg_amop.dat](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/include/catalog/pg_amop.dat). Array I/O defaults follow the header and [Catalog.pm's array-generation rule](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/backend/catalog/Catalog.pm). The inputs are parsed as inert data, never executed. No runtime download, server-observed catalog substitution, grant or migration change is introduced.

The new actual-PostgreSQL cases create safe table/index AM aliases backed by the original native handlers, a deliberately throwing PL/pgSQL comparator on an empty table, and an unsupported predicate. They check refusal before any application query/deparser can run; the comparator is independently called in a rolled-back savepoint to prove the canary works. These tests are authored for the existing disposable TLS lab. Collection and pure unit tests do not count as their SQL execution.

This is storage/callback admission, not a complete source-0017 schema baseline or an exchange-flat proof. The normalized source-0017 baseline and its two independent fresh reference builds remain separate pending work. Neither successful metadata checks nor saved receipts authorize an upgrade, Arm, order, reconciliation claim, or a replacement empty database.
