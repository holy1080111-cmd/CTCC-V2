# Position-history page-chain v1 (offline only)

The [OKX positions-history API](https://www.okx.com/docs-v5/en/#trading-account-rest-api-get-positions-history) returns at most three months of updated positions in descending `uTime` order. Its `after` cursor is a millisecond `uTime`, **not** `posId`, `billId`, or `tradeId`. OKX states that all records sharing the same `uTime` are returned on the current page, including at a `limit=100` boundary. `posId` may expire after a position is fully closed, and the row's close `type` reflects the latest type. These records cannot alone establish complete position epochs or settled funding chronology.

`account_positions_history_v1.py` is a separate, bounded, offline GET-query and response adapter. It pins the region/origin, opaque account/session binding hashes, cutoff, exact `after` query, page index, previous-page hash, source row identity `(posId,uTime)`, raw and canonical body hashes, and page/chain hashes. It accepts equal-`uTime` rows within one page, requires strictly older timestamps on the next page, and allows an over-100 response only when every overflow row ties the 100th timestamp. When OKX supplies `inTime`/`outTime`, each row's `uTime` must be no later than gateway `outTime`, which itself must precede the host's header receipt. Unexpected duplicate identities, changed values, reversed order, nonadvancing cursor, malformed timestamps or financial strings, excessive bytes/rows/pages, a missing page, or no explicit empty terminal deny the chain. Missing financial values remain missing; they are never converted to zero. The cutoff field records whether an observed row crossed the chosen threshold; it does not claim exchange retention or finality.

The adapter has no signing, credentials, network, database, portfolio materialization, or trade-authority path. Its outputs permanently report `account_complete=false`, `source_authenticity_verified=false`, `execution_authority=false`, and `DENY`. Future integration must independently authenticate the exact Demo account/session and source request, persist/read back original raw pages, reconcile positions-history cumulative amounts with fills and bills, and prove the historical tail before any portfolio claim. The finite endpoint cannot prove pre-retention absence or point-in-time availability by itself.

`freeze_chain` now produces a bounded canonical archive after replaying every raw page. `verify_archived_chain` reads those bytes back against an independently supplied plan and SHA-256 pin, reconstructs exact queries and page links, and replays raw bodies, clocks, empty terminal, and the chain digest. The archive preserves original bytes using base64 and is capped at 6 MiB; pages retain their existing individual and total limits. It contains private response bodies and belongs in the same protected storage as account capture. These functions perform no storage or acquisition themselves. A matching external pin establishes byte integrity only: even a successfully replayed archive remains DENY with authenticity, completeness, and execution authority false. This additive format does not extend the existing account-capture stream inventory or certify correspondence with an existing account packet.

`account_positions_history_collector_v1.py` adds a separate, bounded Demo-only signed GET path. It first reads `account/config`, checks the exact `uid`, `mainUid`, account level, position mode, and reported `settleCcy` against a pinned identity digest, follows the history endpoint using only its `uTime` `after` cursor until an explicit empty terminal, then reads config again and requires the same original config row. Every request uses the pinned region's origin and `x-simulated-trading: 1`, one isolated TLS-verified client, no proxy, redirects or retries, no cookies, a bounded response stream, and request/header/body clocks. A separate replay checks the raw config bodies, full history archive, plan/session/account digests, chronology, and SHA-256 before returning. Synthetic tests use a private MockTransport seam and carry no network provenance. The signed collector has not been run against a real OKX account. The config `settleCcy` identifies the account's USD-margined contract settlement setting; instrument settlement still needs separate metadata.

The returned archive remains `DENY`: its stored TLS certificate hashes are self-reported metadata after serialization, not a durable cryptographic attestation. A caller must preserve this sensitive archive in protected storage and pin its hash independently. The caller-supplied session label is not an independently issued credential-session witness; another API key with the same label could satisfy that local hash check. The exact account-config identity check narrows this risk but cannot certify the credential lifecycle. The collector does not establish the account's registration region, prove the three-month retention tail or earlier absence, reconcile cumulative position values with fills and bills, write a database journal, or supply any portfolio/risk/qualification authority. Its private Demo credential and session binding are required at collection time; the archive contains neither credential values nor signatures.
