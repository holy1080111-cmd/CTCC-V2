# Position-history page-chain v1 (offline only)

The [OKX positions-history API](https://www.okx.com/docs-v5/en/#trading-account-rest-api-get-positions-history) returns at most three months of updated positions in descending `uTime` order. Its `after` cursor is a millisecond `uTime`, **not** `posId`, `billId`, or `tradeId`. OKX states that all records sharing the same `uTime` are returned on the current page, including at a `limit=100` boundary. `posId` may expire after a position is fully closed, and the row's close `type` reflects the latest type. These records cannot alone establish complete position epochs or settled funding chronology.

`account_positions_history_v1.py` is a separate, bounded, offline GET-query and response adapter. It pins the region/origin, opaque account/session binding hashes, cutoff, exact `after` query, page index, previous-page hash, source row identity `(posId,uTime)`, raw and canonical body hashes, and page/chain hashes. It accepts equal-`uTime` rows within one page, requires strictly older timestamps on the next page, and allows an over-100 response only when every overflow row ties the 100th timestamp. When OKX supplies `inTime`/`outTime`, each row's `uTime` must be no later than gateway `outTime`, which itself must precede the host's header receipt. Unexpected duplicate identities, changed values, reversed order, nonadvancing cursor, malformed timestamps or financial strings, excessive bytes/rows/pages, a missing page, or no explicit empty terminal deny the chain. Missing financial values remain missing; they are never converted to zero. The cutoff field records whether an observed row crossed the chosen threshold; it does not claim exchange retention or finality.

The adapter has no signing, credentials, network, database, portfolio materialization, or trade-authority path. Its outputs permanently report `account_complete=false`, `source_authenticity_verified=false`, `execution_authority=false`, and `DENY`. Future integration must independently authenticate the exact Demo account/session and source request, persist/read back original raw pages, reconcile positions-history cumulative amounts with fills and bills, and prove the historical tail before any portfolio claim. The finite endpoint cannot prove pre-retention absence or point-in-time availability by itself.
