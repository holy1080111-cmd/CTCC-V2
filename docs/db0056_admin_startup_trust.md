# DB0056 administrator startup reference

The native read-only monitoring candidate can read its deployment pins from
`/run/ctcc-native/0056-startup-trust.json`. The deployment administrator
controls the filesystem and supplies these pins after reviewing the deployed
source, archive, descriptor, and restricted-role policy. The runtime identity
must have independent, read-only access to this reference. The operating
system establishes custody under its administrator account. A named reviewer
or cryptographic signature requires a separate attestation.

The administrator also controls service launch, the deployed executable
and Python environment, and the process, user, and mount namespaces. A
runtime created by an untrusted user inside its own namespace cannot establish
administrator custody by assigning its own apparent root UID. Configure the
service without access to the container management socket, elevation helpers,
or untrusted writable import locations. Administrator-configured UID
remapping may be used when root ownership and permissions in the service
namespace still represent administrator control.

The service runs under a dedicated nonroot UID. Linux deployments provide
`/proc/self/status`, use matching nonzero real, effective and saved UIDs, and
drop permitted, effective and ambient capabilities. All directories from
`/` through `/run/ctcc-native` must be root-owned and must deny group, public,
and runtime writes. The leaf must be a root-owned regular file with mode
`0444` and exactly one hard link. The reader refuses symbolic links anywhere
in the path and checks that the opened files still match their directory
entries after reading. If `/run` is ephemeral, deployment must supply the
reference again following a host reboot.

Use canonical JSON as generated by `app.domain.source_primitives.canonical`
with these exact keys:

| Key | Value |
| --- | --- |
| `schema` | `ctcc.native_only.db0056_admin_startup_trust.v1` |
| `database_head` | `0056` |
| `startup_mode` | `read_only_control_monitoring` |
| `descriptor_sha256` | SHA-256 of the exact owner-verified private descriptor bytes |
| `source_commit` | Exact reviewed 40-digit Git commit ID |
| `source_tree` | Exact reviewed 40-digit Git tree ID |
| `source_archive_sha256` | Reviewed source archive SHA-256 |
| `source_manifest_sha256` | Reviewed source manifest SHA-256 |
| `tls_ca_sha256` | Expected TLS CA bytes SHA-256 |
| `restricted_role_identity_sha256` | Expected restricted-role identity SHA-256 |
| `inherited_native_definitions_sha256` | Expected inherited definitions SHA-256 |
| `granted_inherited_acl_shape_sha256` | Expected granted inherited ACL shape SHA-256 |
| `reviewed_portable_reference_sha256` | Reviewed portable reference SHA-256 |

All hexadecimal values must be lowercase. The reader returns the pins and
the trust file's own SHA-256 for comparison with deployment and database
observations.

## Provision the reviewed reference

Export the [owner-verified deployment descriptor](db0056_deployment_descriptor.md)
first. Retain the descriptor SHA-256 from that reviewed export independently
of the transferred file. Stage an administrator-owned private copy of the
descriptor for installation and another equal-byte private copy for the
runtime UID. The administrator-staged descriptor and its parent directory
must deny group and other access.

On Linux, use the root-controlled exact source and validation environment
whose archive you reviewed. All ancestors of the installed source, descriptor,
and archive must be root-owned directories without group or other write
access. Source files in the application and command directories must also
be administrator-owned and deny group or other writes. The archive must
be a root-owned regular single-link file without
group or other write access. Use full absolute paths. This command belongs
to the deployment administrator and accepts no database credentials.

    python -B -m scripts.install_native_startup_trust_0056_v1 \
      --descriptor-file /private/admin/db0056-deployment-descriptor.json \
      --descriptor-sha256 <digest retained from the reviewed owner export> \
      --source-archive-file /reviewed/CTCC-source.tar

The command checks the descriptor, exact installed release and portable
database reference before atomically publishing the fixed path. Linux and
the filesystem at that path must support no-clobber rename. A matching
existing root-owned file returns exit code 0 with status ALREADY_INSTALLED.
A conflicting or malformed existing file returns exit code 1 and is
preserved. Both success states report the observed reference hash. The
commands here leave service startup, account arming and writes outside the
reference installation.

For rotation, stop the affected monitoring process and use the administrator's
preserved deployment rollback procedure to move the prior reference out of
the fixed path. Install the independently reviewed replacement and verify the
new runtime readback before restoring the process. The installer does not
automatically replace or remove an active reference.

## Read back the stored control

After verifying the deployed runtime and installing the administrator
reference, run the following from the installed exact source as the dedicated
runtime identity. Use its three restricted PostgreSQL logins and pinned TLS
CA. The deployment descriptor file must be private to that identity. The
archive and descriptor must match the independently installed reference.

    python -B -m scripts.native_control_status_0056_v1 \
      --descriptor-file /path/to/private/db0056-deployment-descriptor.json \
      --source-archive-file /path/to/exact-release.tar

Exit code 0 reports two identical stored-control observations around a fresh
three-role readback on one PostgreSQL incarnation. The stored Arm flag refers
to the database row. The command reports the control as stored in PostgreSQL.
Exit code 1 means the installed source, trust reference, role boundary, or
stable control could not be verified.
