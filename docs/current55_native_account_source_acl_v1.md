# DB0055 native account source writer ACL delta v1

The additive plan begins with an exact, committed core installation and applies eleven table grants to its existing restricted writer. The core module, core receipt and the raw frame and custody roles keep their existing contracts. The delta is intentionally separate from the core provisioner, whose initial and final ACL checks require the precise core-only matrix.

| Path | Tables | Rights |
| --- | --- | --- |
| B1 history and CURRENT capture journal | `demo_account_capture_events` | SELECT, INSERT |
| B3 observed history batches and members | `demo_account_observation_batches`, `demo_account_observation_facts`, `demo_account_observation_coverage`, `demo_account_observation_findings` | SELECT, INSERT |
| B5 local mirror inventory | `demo_automation_state`, `okx_demo_order_state`, `okx_demo_position_state`, `okx_demo_algo_order_state` | SELECT, MAINTAIN |
| B5 mirror checkpoint | `okx_demo_sync_checkpoints` | SELECT, INSERT, UPDATE |
| B5 mirror audit | `audit_logs` | SELECT, INSERT |

B1 uses `AccountCaptureJournalRepository._append` and separate committed readback. The current controlled path in `account_current_source_v4.py` delegates to `_capture_initial_current`, whose journal is B1. B3 follows `native_controlled_account_source_v6._history_v6` through `account_history_source_v1._acquire_native_history_controlled_asof_v4` to the untyped `AccountObservationIndexRepository.append`, which adds batches, facts, coverage and findings and reads them back. The typed and legacy CURRENT observation-index paths are separate. The B3 call leaves the optional HWM prefix check off. Controlled V6 writes the measured HWM evidence through the existing custody RPC, so this delta adds no grants to the optional legacy HWM table.

B5 reads the five fixed local tables under SHARE in `QualificationLedgerRepository._read_portfolio_checkpoint_locked`. The current55 mirror takes SHARE ROW EXCLUSIVE on those same tables before writing. PostgreSQL 17 accepts MAINTAIN for these locks without DML rights. Checkpoint UPDATE already permits both lock modes and needs no additional MAINTAIN. MAINTAIN also permits maintenance operations on the named relations, including operations beyond these locks. The table grants permit access at table scope. The application continues to select its exact columns and identities. [PostgreSQL 17 LOCK](https://www.postgresql.org/docs/17/sql-lock.html) · [PostgreSQL 17 privileges](https://www.postgresql.org/docs/17/ddl-priv.html)

The mirror uses ORM insert or update on the singleton checkpoint and inserts and rereads the audit row. Checkpoint ID is explicit and the audit ID is generated by the UUID model, so neither path needs a new sequence grant. These grants do not cover any other service startup, paper storage, generic Demo mirror synchronization or older observation adapters.

`current55_native_account_source_grant_sql_v1` renders the fixed statement set for review. `provision_current55_native_account_source_acl_v1` accepts two already-open idle connections for the owner and the genuine restricted writer, with the three precreated core login names. It verifies the sealed actual writer catalog and original B1/B3 source catalog in a separate read-only transaction, with the same database and different backend and transaction IDs. The owner transaction shares the core provisioning lock, verifies exact effective core rights, holds the delta relation identities and refuses unexpected ACLs or relation shapes. It rereads exact combined permissions and unchanged core identities before commit. Use an exclusive deployment window. A lost commit acknowledgement requires an independent ACL observation before any further action.

The receipt explicitly marks direct login readback and the complete runtime role matrix as pending. In a disposable PG17 fixture, independently reopen all three logins after commit, compare exact positive and prohibited privileges, exercise the actual five-table SHARE and SHARE ROW EXCLUSIVE locks, and verify the expected checkpoint and audit operations with rollback. Revoke one required lock grant or add an unexpected right in a separate fixture and verify that the operation fails without widening privileges. Run the existing writer, frame and custody role guards again. None of these checks supplies execution authority.
