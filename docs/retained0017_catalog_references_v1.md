# Fresh source17 catalog reference custody

The current source58 PostgreSQL owner component3 must run both parameterized
`test_actual0017_fresh_independent_catalog_reference_is_complete` cases. Each
case creates a different empty database from template0, a different dedicated
non-superuser owner without role memberships, and genuinely applies the
reviewed migration prefix through0017. No retained host database, account
credential, exchange call, Arm or order participates.

The reference migration uses the canonical environment's registered
`Base.metadata`, naming convention and `compare_type=True` context. Unnamed
constraints receive their genuine migration names; the reference does not
rename constraints to make independently created catalogs agree.

Each case preserves the actual raw catalog, the source-defined normalized
catalog, and a source-bound receipt. The receipt retains its distinct database,
owner and version-marker object OIDs, TLS observation and exact role flags.
Only this disposable fixture's existing TLS trust route is exercised; these
references do not prove password authentication or production provisioning.

The post-test source58 component verifier requires all six files. It replays
the genuine comparator against each raw catalog, verifies the source commit,
tree, archive, manifest, migration inventory, exact producer/comparator bytes
and the source17 prefix hash, and requires both full normalized catalogs to
have the same SHA256. Missing files, mixed prefixes, changed catalog hashes or
reused database/owner/version-marker identities fail the component even when
both individual JUnit cases passed. The complete source58 union also requires
this pair proof exactly once from component3.

The comparator's literal reference remains pending until the actual hosted
artifacts are independently reviewed. Test output, two equal reports, a caller
digest or these receipts never install that seal or authorize a schema upgrade,
runtime startup, reconciliation or trading. Preserved row contents, actual
sequence values, physical identities and unknown legacy intents remain part
of the separate retained-state proof; they are not compared to an empty fresh
database or removed to make the schema match.

measurements are unchanged. These source17 references are a source58-only
schema comparison gate.
