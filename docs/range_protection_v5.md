# Explicit neutral-range protection V5

V5 adds `ctcc-neutral-range-protection-v1` alongside the original
`ctcc-original-range-anchor-v1` restriction. Prefix policy, qualification,
pre-evidence policy/run, evidence run, current conditions and fixed protection
all select explicit V5 contracts. These are computational contracts, not source
or execution authority. Existing V1–V4 defaults, receipts and behavior remain
unchanged. V4 still stops at its original G8 `source_data_blockers` and reservation
`ledger_range_policy_incomplete` denial.

The user's requirement for strategy-specific reversal structure permits this new
policy. It does not imply that the unavailable integrated helper has been
recovered. The original expected SHA-256 remains documented with V4; V5 makes no
claim to reproduce that unreviewed helper. The existing eight strategy modules,
regime classifier and their numeric thresholds are unchanged.

## Source-derived policy

Each original evaluation rebuilds quality and analysis from the raw market at
the original observation time, then uses `route_regime` and the existing
`range_reversal` condition assessment. Structural selection independently
repeats the analysis, source identity, closed-bar event and original TTL replay.

Required permission consists of the existing Range route with `ALLOW_SCORING`
and range-reversal membership. It preserves neutral 4H and 1H trend and bias,
intact actual support/close/resistance bounds, absence of 15m BOS/CHoCH, and
normal/low 15m volatility. Existing data-quality, instability, volatility,
compression, malformed snapshot, other analysis blockers, directional,
required-condition, veto and mathematical-risk conditions remain effective.
Only `multi_timeframe_not_aligned` is no longer a blanket G8 rejection in this
new range-specific selector. It remains unchanged in analysis and is retained
in the structural audit and G3 measurements.

The actually used 15m ATR must exist and be positive; the existing strategy's
price-based ATR fallback is not admitted. The 5m MACD histogram and RSI operands
must exist. A mathematical-core snapshot must exist; the existing unstable,
opposed and blocked-risk vetoes apply. No new score, indicator, reliability or
mathematical-status threshold is introduced. G4 retains the original minimum
score, fresh quote spread and adverse funding gates.

G5/G6 retain the original closed range-edge reclaim, pivot chronology, 5m
momentum transition and timing policy. G7 intersects the original zone with the
original anchor/one-ATR band and rounds inward to the instrument tick. G8 uses
the existing structural anchor universe, buffer/noise/thesis checks, nearer
target rejection, costs and ranking. A new digest binds the explicit range
permission. G9–G11 retain existing economics, leverage and portfolio checks.

## Publication and current replay

G12 uses the existing renderer, six artifacts, no-clobber publisher and actual
readback logic. A receipt or hash cannot upgrade an old denied candidate.
R7 replays original G1–G12, then current source G1–G4, original event survival,
original timing/zone, fixed SL/TP, executable economics and current risk. Current
G1–G4 do not extract a replacement event. Fixed protection replays the original
selector and tests the current source against the same bracket; it does not
select new prices. Entry, event, zone, policy and expiry are not extended or
reinterpreted. Improved execution prices cannot repair an originally failed
candidate.

## Reservation and durable-intent boundary

`ReservationRequestV3` is explicit and range-V5-only. Its mandatory
`ReservationReplayBindingV3` includes the bounded canonical account packet and
its packet/plan hashes, plus canonical original/current market, original inputs,
raw collected quote, WS reference, recorded recheck and consumed event keys.
Control-bound reserve verifies that packet's exact UID, settlement currency, and
credential-session pin before creating a hold. Historical V2 requests remain
decodable, but lack the pre-reserve account packet and are rejected by the
control-bound route. Before caps, the shared reserve/consume preparation replays original
G1–G12 and the entire recorded R7, pins its exact origin/quote/risk inputs, and
reruns R7 at the current locked observation time. Missing documents, mixed
versions, duplicate event keys, changed claims, expiry and failed replay deny.
The account's stored current claims must equal the supplied risk inputs. The
repository also pins the exact account revision at reserve and consume; a newer
revision cannot silently reuse an old binding. Existing active holds remain in
the aggregate risk calculation. No table/schema change is made.

V5 cannot build legacy intent-v1. Intent-v2 requires the complete account page
chain and execution binding, which must also match every reservation replay
document. It replays raw sources again and retains the existing exact FOK sample,
size, leverage, margin mode, protection IDs, request hash and durable readback.
This is still a journal derivation, not a submit permission. The shared final
transport continues to reject non-authoritative computational records.

## Validation limits

The dedicated fixture declares a raw historical bracket before qualification.
It does not mutate an accepted candidate, select a replacement trigger, replace
an evaluator result or loosen a risk/economic threshold. The prior narrow-range
fixture remains a genuine `no_valid_structural_bracket` V5 denial. A separate
memory-directory test runs actual rendering, publication hashes and readback;
it proves the pure protocol only, not native Windows filesystem durability,
TLS provenance, a genuine Demo account, real Shadow evidence or profitability.
Native publication, PostgreSQL concurrency and exchange acceptance are reported
separately and require actual execution. No synthetic computational PASS is a
production acceptance result. Sweep HTF policy is outside this profile.
